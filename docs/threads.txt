A threads is a new sub-instance of the virtual machine that runs in
parallel to the main instance. This instance shares a heap with the
main instance, but has an independent register file. An arbitrary
number of threads may be spawned. The contents of the register file from
the thread which is spawning the thread in reference, known as the parent
thread, is used as the initial register state in the new thread being
spawned, known as the child thread. The program will exit once the main
thread exits or a halt is performed. When the multi flag in the binary
header is set, memory locks will be enabled. This allows all memory
instructions to appear atomic to the application, preventing memory
races completely. It should be noted that memory operations, specifically
writes, are a good bit slower with this enabled.

This may not need to be enabled if threads are not used or the program
can guarantee two threads will not write to the same address at the
same time, eg. if the application implements it's own form of locking.

Common cases for this include code that only uses registers, code which
dedicates explicit regions of memory to each thread, and code that only
uses memory for stack operations, where each thread has a separate stack
pointer.

It is encouraged to not use the multi flag unless specifically needed.
